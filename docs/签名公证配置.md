# macOS 签名与公证配置指南

ETFWorld 的发布流水线（`.github/workflows/release.yml`）内置了 Apple 签名 + 公证链路，
配置好之后打出的 DMG 下载即用，不会再出现「无法验证开发者」的 Gatekeeper 警告。

前置条件：已加入 [Apple Developer Program](https://developer.apple.com)（个人/公司均可）。

## 一、准备 5 个 Secrets

在仓库 **Settings → Secrets and variables → Actions → Secrets** 里逐项新建：

| Secret | 怎么拿 |
| --- | --- |
| `APPLE_CERT_P12` | 见下方「导出证书」 |
| `APPLE_CERT_PASSWORD` | 导出 .p12 时你自己设的密码 |
| `APPLE_ID` | 你的 Apple ID 邮箱 |
| `APPLE_APP_PASSWORD` | 见下方「App 专用密码」 |
| `APPLE_TEAM_ID` | [developer.apple.com/account](https://developer.apple.com/account) → Membership 页的 **Team ID**（10 位字符） |

### 导出证书（APPLE_CERT_P12）

1. 打开「钥匙串访问」→ 登录钥匙串 →「我的证书」，找到
   **Developer ID Application: 你的名字 (TEAM_ID)**。
   - 没有的话：钥匙串访问 → 证书助理 → 从证书颁发机构请求证书，
     然后去 [Certificates 页面](https://developer.apple.com/account/resources/certificates/list)
     新建 **Developer ID Application** 类型证书并下载双击导入。
2. 右键证书 →「导出」→ 格式选 **.p12**，设置一个导出密码（即 `APPLE_CERT_PASSWORD`）。
   注意要导出**含私钥**的条目（展开证书选中证书+私钥一起导出，或直接右键证书条目导出）。
3. 转 base64 并复制：
   ```bash
   base64 -i ~/Desktop/certificates.p12 | pbcopy
   ```
4. 粘贴为 Secret `APPLE_CERT_P12` 的值。

### App 专用密码（APPLE_APP_PASSWORD）

1. 打开 [appleid.apple.com](https://appleid.apple.com) → 登录与安全 → **App 专用密码**；
2. 生成一个（备注可写 `ETFWorld notarize`），形如 `xxxx-xxxx-xxxx-xxxx`；
3. 粘贴为 Secret `APPLE_APP_PASSWORD` 的值。

## 二、打开开关

仓库 **Settings → Secrets and variables → Actions → Variables** 新建：

- Name: `MACOS_SIGNING`，Value: `true`

不配这个 Variable 时流水线行为和以前完全一致（不签名，直接出未签名 DMG）。

## 三、验证

不用发版就能验证：仓库 **Actions → release → Run workflow** 手动触发一次
（`workflow_dispatch` 触发只构建+签名+公证，不会上传/覆盖 Release）。

跑完后在 runner 日志里应看到：

- `签名 .app` 步骤：`codesign --verify` 无报错；
- `签名并公证 DMG` 步骤：`notarytool` 状态 `Accepted`，`stapler validate` 通过。

本机复核（把 CI 产物或本地构建的 DMG 下载后）：

```bash
hdiutil attach ETFWorld-macos-arm64.dmg
spctl -a -vv /Volumes/ETFWorld/ETFWorld.app        # 应输出 accepted, source=Notarized Developer ID
xcrun stapler validate ETFWorld-macos-arm64.dmg    # 应输出 The validate action worked!
hdiutil detach /Volumes/ETFWorld
```

## 常见问题

- **notarytool 报 Invalid credentials**：App 专用密码错了，或 Apple ID 开了双重认证却用了登录密码。
- **codesign 找不到证书**：`导入签名证书` 步骤的 `security find-identity -v` 输出里应能看到
  `Developer ID Application`；看不到说明 .p12 没带私钥或密码错。
- **公证能过但启动闪崩**：一般是 hardened runtime 权限问题，确认签名步骤带了
  `--entitlements assets/entitlements.plist`（流水线已内置）。
