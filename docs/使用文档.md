## 1. 系统简介

ETFWorld 把指数估值、ETF 查找、网格规划、执行跟踪、组合管理和复盘放进一个桌面应用。核心策略是**网格交易**：

- **网格 1.0**：从基准价开始，每下跌一格买入一份，价格回升一格卖出，赚取差价。低买高卖、机械执行。
- **网格 2.0（留利润）**：每次卖出时保留一部分利润对应的份额不卖，长期积累零成本底仓，兼顾长期上涨。

档位价格几何对称：**买入价 = 基准价 × (1−格距)ⁱ，卖出价 = 买入价 ÷ (1−格距)**——第 i 格的卖出价恰好是上一格的买入价。

产品边界：不连接券商、不自动下单、不预测涨跌、不承诺收益、不提供个性化投资建议。

## 2. 安装与启动

### 桌面版（macOS）

从 Releases 下载 `ETFWorld.app` 移入"应用程序"即可。用户数据存放在 `~/Library/Application Support/ETFWorld/`，升级或移动 App 不影响数据。

### 源码运行

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements.txt
python desktop.py
```

或 Web 开发模式：`python -m uvicorn backend.api.main:app --reload`，访问 <http://127.0.0.1:8000>。

### 首启向导

首次启动（未配置数据源或库内无数据）会自动进入三步向导：**阅读免责说明 → 填入 Tushare Token（保存并测试连接）→ 回填历史数据**。向导只出现一次，之后可随时在右上角「⚙ → 首启向导」重新进入。

## 3. 配置

右上角「⚙ → 设置」弹层中配置，保存即生效：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| Tushare Token | 在 tushare.pro 注册获取 | （必填，数据源） |
| Tushare API 地址 | 自定义数据通道，**不可改成官方地址，否则会报 Token 不对** | https://ttx.dailyfetch.top/ |

## 4. 首页

打开应用的第一屏，回答"我的组合和整个市场现在什么状态"：

- **理念带与快捷入口**：今日待办 / 开新网格 / 查看组合。
- **快照卡**：总资产、待办数、预警数、运行计划、套利回合、满格资金占比，点击直达对应页面。
- **市场估值地图**：全部监控指数按 5 年估值分位打在 0-100% 色带上（点位可点击进详情）；下方分带列出 低估区·可开网候选 / 中性区·等待 / 高估区·只卖不买 三栏。
- **今日市场快照**：20 日动量最强/最弱、估值越界名单。
- **功能导览卡**：新用户的页面指引。

## 5. 今天

待办驱动的驾驶舱，每天打开先看这里：

- **今日待办**：距现价 <2% 的买/卖档位清单（方向、标的、档位价、份额、金额、所属计划、距触发百分比）。网格不自动下单，照着去券商挂单后点「知道了」。
- **预警灯**：
  - **破网**：现价跌破最低档，网格失效，点「处置」进入三选一（装死持有 / 向下接网 / 止损归档）；
  - **高位运行**：现价高于基准价，卖无可卖，可「上移重开」——**重开前会先检查估值分位**，分位 >50% 时给出警告；
  - **估值越界**：持仓品种分位涨过 50% 否决线，建议只卖不买。
- **组合概览条**：本金 / 现金 / 满格占比速览。
- **机会精选与最新成交**：雷达当前 GO 级标的、最近几笔成交。

## 6. 机会

雷达 + 估值的合并视图，回答"现在能开网格吗"：

- **评分表**：全部监控指数按就绪度评分降序（估值安全垫 70 分 + 波动充足度 30 分，分位 >50% 直接否决），含估值分位、年化波动、建议格距、四档结论（适合开启 / 可小仓试探 / 观望 / 不建议）。
- **指数详情抽屉**（点击任意行）：多周期估值带（3y/5y/10y/全历史）、PE/PB 与历史中位、20/60/120 日动量、距 52 周高点、AI 研判入口、「以此标的去规划」一键带入。

## 7. 规划

网格规划器，回答"这张网怎么设计"：

1. **找标的**：搜索 ETF（名称/代码，按成交额排序），选定后自动带出最新价作为基准价。
2. **定参数**：基准价、格距、格数、每格金额、逐格加码（越跌买得越多）、留利润（启用即 2.0）。
3. **看档位表与压力测试**：每格的买入价/卖出价/金额/份额（按 100 股整手取整）/卖出与留存份额/预期收益；满格资金需求与最深浮亏——先算最坏情况再开网。
4. **回测验证**：近一年真实行情模拟（网格 vs 一直持有的净值曲线、套利次数、资金利用率、破网标注）。回测基准价取窗口起点价，未计手续费与滑点，仅用于理解策略特性。
5. **参数寻优**：格距 × 格数的风险调整收益扫描，给出当前行情下的较优组合。
6. **存为计划**。

## 8. 计划

每个计划是一个完整的归档单元：参数 + 执行状态 + 成交记录。

- **计划列表**：全部计划与状态（ACTIVE / PAUSED / BROKEN / CLOSED），满格资金合计口径见表下注释。
- **计划详情**（点击计划）：
  - **档位执行状态棋盘**：每格四态——待买（无成交）/ 持有（有买未卖）/ 已卖（买卖相抵）/ 留存（卖出后留下的零成本份额），由成交记录自动推导；
  - **现价标尺**：现价在网格区间里的位置；
  - **成交记录**：录入时按方向和价格**自动匹配档位**（±1.5% 容差），也支持手动指定；
  - **AI 计划体检**：对参数与压力测试做"最脆弱点"分析；
  - **状态操作**：暂停 / 恢复；BROKEN 计划显示破网处置三选一。
- **删除**支持撤销。

## 9. 组合

三账户视图，回答"若全部网格买满，我的钱够不够"：

- **三账户**：底仓（录入成交时不关联计划即计入）/ 网格持仓（按计划分组）/ 现金（= 本金 − 持仓成本）；网格 2.0 的留存份额作为零成本底仓单列。
- **安全线**：ACTIVE + PAUSED 计划满格资金合计 ÷ 本金，超过 70% 给出警告——破网的代价从来不是浮亏，是没钱补网。
- **资金流水**：本金 = Σ入金 − Σ出金，记流水后安全线与现金自动更新。

## 10. 复盘

杂志模式的阅读页（排版与其他页不同是有意的场景切换）：

- **合计**：套利回合（一次完整买→卖）、已实现收益、留存底仓市值、纪律违约次数。
- **AI 周报复述**（需配置 AI）：把本周数据复述成"本周做了什么 / 纪律检查 / 下周关注"，按周缓存。
- **分计划复盘**：回合、已实现、留存、违约计数。
- **收益构成**：网格已实现 vs 底仓浮盈 vs 留存浮盈——上涨市里底仓占比高是正常的。
- **纪律判定口径**：日线收盘穿越档位价（±1% 容差）且 7 个交易日内无对应方向成交，记 1 次违约；买入义务只在未持有时、卖出义务只在持有时评估，同一波穿越只记一次。

## 11. AI 服务（可选）

可接入任意兼容 OpenAI Chat Completions 协议的服务。在「⚙ → 设置」填入 API Key、地址、模型名并保存，可点「测试连接」验证。

- **指数研判**（机会页抽屉）：服务端组装全量上下文（PE/PB 与历史中位、多周期分位、动量、波动、规则分）后生成结论、深入解读、关键依据、风险提示与参数倾向。
- **计划体检**（计划详情）：针对具体参数与压力测试找最脆弱点。
- **周报复述**（复盘页）：组合级周报。
- 定位是研究助手：只做数据解读与风险提示，不输出买卖指令；结果按（标的, 数据日期）缓存；推理型模型响应较慢（数十秒）属正常。Key 只保存在本机后端配置。

## 12. 命令行工具

不开网页也能用命令行操作（项目根目录执行）：

```bash
# 初始化数据库
python3 -m backend.init --init-db

# 更新最新估值数据
python3 -m backend.init --update

# 回填历史数据
python3 -m backend.init --backfill --start 20150101 --end 20261231

# 查看当前估值概览
python3 -m backend.init --show

# 网格就绪度评估（红绿灯排序）
python3 -m backend.init --readiness

# 申万行业搜索 / 列表
python3 -m backend.init --sw-search 白酒
python3 -m backend.init --sw-list L2

# 找标的：搜索可交易ETF（按成交额排序）
python3 -m backend.init --etf-search 证券
```

## 14. 常见问题

**Q：估值页全是空的 / 显示 `-`？**
A：还没有数据。完成首启向导的回填，或执行 `python3 -m backend.init --backfill --start 20150101 --end 20261231`。

**Q：分位点不显示？**
A：分位点需要至少 30 个样本才计算，历史数据太少时为空。建议回填 5 年以上。

**Q：提示 Tushare「Token 不对」？**
A：检查 API 地址必须是自定义数据通道（默认 `https://ttx.dailyfetch.top/`），见 `backend/services/tushare_init.py`。

**Q：端口 8000 被占用？**
A：换端口启动：`python3 -m uvicorn backend.api.main:app --port 8080`

**Q：数据存在哪？**
A：桌面版在 `~/Library/Application Support/ETFWorld/`；源码运行在项目根目录的 `etfworld.db`（SQLite）。删除数据库文件即可清空所有数据。

**Q：网格份额为什么和「每格金额 ÷ 价格」对不上？**
A：份额按 100 股（1 手）向下取整，实际买入金额会略小于设定值，这符合 A 股交易规则。

**Q：雷达里波动率后面的 `*` 是什么意思？**
A：表示该指数没有收盘价数据，波动率是用 PE 序列代理估算的。申万行业有真实收盘价，部分宽基指数用代理值。

**Q：AI 研判点了没反应或报错？**
A：先在「⚙ → 设置」检查 Key 与模型名（推理型模型响应需数十秒，属正常）；未配置时相关入口自动隐藏，其他功能不受影响。

**Q：雷达带入规划器的基准价不对？**
A：雷达带入的是指数点位，不是 ETF 价格。请以「找标的」选定 ETF 后的实际价格为准。
